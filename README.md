# Portfolite — Framer export (organized)

This is a locally-hostable static export of the **Portfolite** portfolio template
that was exported from Framer. The visible design, animations, responsive
breakpoints and interactions are unchanged from the original export — only the
file layout and asset/reference paths were reorganized.

## Run locally

The site uses a few root-relative URLs generated by Framer's runtime, so it must
be served over HTTP (opening `index.html` directly with `file://` is not
supported, exactly as with the original export).

```bash
# Python 3
python -m http.server 8080

# then open http://localhost:8080/
```

Any static server works (`npx serve .`, `php -S localhost:8080`, etc.).
No build step, package manager or backend is required.

```
│   ├── services-visual.css     # Services screenshot container

│   └── icons/                  # SVG icons and favicon artwork
└── js/
    ├── events.js               # Framer analytics/events script
    ├── contact-section.js      # Mounts #contact + form validation + nav link fix
    ├── services-visual.js      # Replaces the device mockup with a static screenshot
    ├── image-updates.js        # Applies the uploaded FAQ image
    ├── navigation-updates.js   # Header links + project-view anchor fixes
    ├── button-standardize.js   # Clones the Framer button for the 3 non-Framer CTAs
    ├── footer-social.js        # WhatsApp/GitHub footer links + mailto email
    ├── metadata-guard.js       # Enforces title/meta and removes guessed deploy URLs
    ├── projects-diversify.js   # 4 Red Bull + 4 VERDÉ project cards

    │                           #   — must stay together: modules import each other by
    │                           #     relative ./filename.mjs paths
    └── vendor/                 # Optional Framer-provided icon modules / editor helper
```

## Notes

- **Why the runtime bundle is kept as one folder:** the `.mjs` files import each
  other with relative paths (e.g. `./react.BF5K0J5z.mjs`). Moving them
  individually would break the website's hydration, animations and interactions.
- **Font CSS:** the original `@font-face` rules were moved out of `index.html`
  into `css/fonts.css`. They are otherwise byte-for-byte identical; URL paths
  were updated to point at `assets/fonts/`.
- **Inline URL rewrite:** `index.html` contains a small Framer-export helper that
  rewrites any remaining `framerusercontent.com/...` image URLs at runtime to
  local `assets/...` paths. Its lookup table was updated during the reorganization.
- **External URLs:** the Framer icon modules are now loaded from the local
  `js/vendor/phosphor-icons/` wrappers (which import the bundled modules in
  `js/vendor/modules/`). The icon loader in `js/framer/toplevel-deps...mjs` uses
  the local directory, so no Framer icon CDN requests are made. Other inert
  third-party URLs in the minified runtime are unused leftovers.
- **Framer watermark:** `css/custom.css` hides `#__framer-badge-container`. The badge
  is injected by the Framer runtime, so it is hidden with CSS rather than deleting
  its container (which would break hydration).
- **Header "Get Template" CTA:** removed from the static HTML and from the rendered
  DOM by `js/navigation-updates.js` (which re-applies after Framer re-renders).
  `css/custom.css` still hides the selector as a fallback. The remaining nav items
  keep their existing spacing.
- **About heading alignment:** the Framer "more info" column centres its children,
  which indented the "Jahid Al Abid" heading relative to the paragraph, skill tags
  and experience list. `css/custom.css` left-aligns just that heading wrapper and
  lifts it 6px with cancelling margins, so the section height and portrait are
  unchanged. Typography, text and other sections are untouched.
- **Contact section:** `#contact` sits between the FAQ section and the footer. It
  uses a 40/60 two-column layout on desktop (intro + WhatsApp card on the left,
  form on the right), narrower columns on tablet, and stacks on mobile. Styles
  live in `css/contact.css`. `js/contact-section.js` mounts it because the Framer
  runtime re-renders the page (plain markup in `index.html` would be erased by
  hydration). The same script repoints the header "Contact" link and all existing
  "Let's Work Together" / "Contact Me" buttons at `#contact`, removing their
  original `target="_blank"` so they scroll this page instead of opening a tab,
  and re-applies those changes if the runtime re-renders.
- **Section alignment:** `html` already sets `scroll-padding-top: 72px` for the
  fixed navbar, so `#contact` deliberately has **no** `scroll-margin-top` (the two
  together would offset it to 144px). A `min-height: calc(100vh - 72px)` makes the
  section fill the area under the navbar so neighbouring sections don't peek in.
  Its entrance animation lives in CSS and always finishes in a visible state.
- **WhatsApp number:** `8801787320204`, configured once in `js/contact-section.js`
  (`WHATSAPP_NUMBER`) and used for the CTA, footer icon and form submission:
  `https://wa.me/8801787320204`.
- **Form:** validates Name, Email Address, Project Type and Project Details with
  inline errors, builds a readable URL-encoded WhatsApp message, opens it in a
  new tab and tells the visitor to press Send. It never claims a message was sent
  and makes no network request. `js/footer-social.js` replaces the template's
  Behance/X/Dribbble links with WhatsApp + GitHub and links the footer email.
- **Services visual:** the laptop/phone mockup and both live iframes were removed.
  `js/services-visual.js` places a single static screenshot of the actual Red Bull
  website in the original image container:
  `assets/images/Ni74vgkuqdIR02d1m4UEqH4TQ.png` (1899x962, already in the export).
  `css/services-visual.css` uses `object-fit: contain` on a `#f2f2f2` background
  matching the screenshot, so its colours, proportions and all content are kept
  and the container's existing 17px rounded corners stay intact. The script
  re-applies the replacement if Framer re-renders the subtree. The obsolete
  `js/mockup-align.js` was deleted.
- **Image updates:** `assets/images/faq-blocks.png` is the exact uploaded FAQ
  image (wooden F/A/Q blocks) replacing the old lemon image in the FAQ container;
  `js/image-updates.js` swaps the source and drops its `srcset`. The original
  Framer wrapper `.framer-98n566` filter is cleared and `grayscale(1)` is applied
  to the FAQ image itself, matching the portfolio's monochrome aesthetic. The
  Services screenshot also has `grayscale(1)`. Both images keep their size,
  position, crop, sharpness and 17px corners; no other image is filtered.
- **Navigation:** `js/navigation-updates.js` removes the header "Testimonials"
  link (desktop and mobile menu) and adds `id="projects"` to the existing Projects
  section. Every project-view CTA ("View my work", "View My Project", "View
  Casestudy") now targets `#projects` and opens in this tab. A window-level
  capture listener performs the scroll because Framer's router otherwise uses
  the component's original link target. Services/Contact links and section
  content/layout are untouched.
- **Button styling:** the three non-Framer CTAs (Projects "View My Project",
  WhatsApp, form submit) are now **exact deep clones of the original Framer
  "Contact Me" component** — same nested wrappers, blurred radial-gradient glow
  divs, gradient values, two-layer border, radii and hover rules. `js/button-
  standardize.js` clones the component, swaps the label/destination, keeps the
  WhatsApp icon inline (the one layout tweak needed so the 16px icon does not
  grow the 46px button), and toggles Framer's `.hover` class on mouse enter.
  `css/button-match.css` also reproduces the original's hover animation exactly:
  the Framer spring easing string and 700ms duration captured from the original
  WAAPI animation drive transitions on opacity, box-shadow, glow bar dimensions
  and a crossfaded gradient overlay — no snapping on hover in or out. It also
  holds resets for a `<button>` clone, removes rich-text underlines, and adds
  the travelling border highlight: a registered
  `--portfolio-border-angle` custom property animated 0→360deg (8s linear,
  infinite) drives a conic-gradient light masked to a 1px ring. The gradient
  uses the component's own greys/white; the original layered glows are untouched
  and hover never restarts the animation. The Framer export contained no border
  animation definition, so its keyframes/timing were reconstructed from the
  supplied screen recording. The hero/Process/Services "View My ..." links
  already use the same Framer component; project-card "View Casestudy" buttons
  use a different component and were not touched.
- **Metadata:** `index.html` now uses Jahid’s title/description for the document,
  Open Graph and Twitter. Canonical, `og:url` and `hreflang` are deliberately unset
  because the Vercel URL is not known yet; `js/metadata-guard.js` removes any values
  the Framer runtime regenerates. Unused search-index metadata and both JSON files
  were removed. Social image URLs stay relative until the production domain exists.
- **Projects:** `js/projects-diversify.js` retargets four of the eight Framer case-study
  cards to VERDÉ using real screenshots captured from the live site (`verde-home.png`,
  `verde-shop.png`, `verde-quiz.png`, `verde-product.png` in `assets/images/`). The
  remaining four stay Red Bull. Card markup, sizes, hover effects, grayscale treatment
  and animations are untouched; VERDÉ project details are stored in accessible
  attributes (no extra visible button was added). `js/navigation-updates.js` skips
  VERDÉ cards so it never rewrites their URLs. Image framing: the home card uses
  `object-position: 10% 50%` (was `55.3% 47.8%`) and the quiz card `75% 50%` (was
  `47% 48.8%`); shop and product remain centered at `50% 50%`.
- **No dependencies were added** and no backend was introduced.
